# OCW Offline — Audit Trail

**Filename convention:** saved as `AUDIT_TRAIL_v(N).md`, `N` matching the round it was last appended in — same reasoning as `PROCESS_v(N).md`, purely to avoid overwriting a previous save on a phone. This is one continuous, ever-growing document across those filenames, not a new file each round. If handed more than one `AUDIT_TRAIL_v(N).md` at once, use the highest N — it's a strict superset of every lower one's entries, never a divergent branch, because nothing is ever edited in place, only appended.

**This file is additive only.** Each round appends one entry. Nothing above is ever edited in place — a correction to an old entry is a new entry that says so and references the old one by round number. This file was constructed for the first time at v13 (this update), from all thirteen `HANDOFF.md`/`HANDOFF_v2.md` through `HANDOFF_v12.md` documents read directly as primary sources — not reconstructed from later rounds' summaries of them, which is what v10's original changelog attempt had to do and flagged honestly as a limitation at the time. Everything below is High confidence (primary source), except where explicitly marked otherwise.

Where something was introduced, then not carried into a later round's text, then reconstructed — that's recorded as three separate facts, not collapsed into one "introduced at round N" line. That pattern is real and has happened at least twice (see v9/v10/v11 entries below); the whole point of this file's shape is to keep it visible instead of smoothing it over.

**v1** — Initial pipeline: scrape → DB → download entry points. Single iOS-first screen, SQLite (sqlite-net-pcl), HtmlAgilityPack scraper against OCW's `/download/` pages, resumable `HttpClient` downloads, iOS backup-exclusion (`NSURLIsExcludedFromBackupKey`). Hard constraints established, both still standing: no YouTube extraction, no multi-user redistribution. Chose .NET MAUI over the original brief's Swift assumption (person's own long-standing .NET background). Documented as "never compiled" from the start.

**v2** — `Artifact`/`Lecture` converted to `ObservableObject` partials (CommunityToolkit.Mvvm) for live UI binding. Wired `ExtractZipAsync` to auto-run after zip downloads (previously existed but unwired). Fixed the `OnProgressChanged` no-op stub to actually update per-row progress. Added storage-total/delete plumbing (`GetStorageUsedByCourseAsync`, `DeleteFile`, `DeleteCourseFolder`) and two converters (`StringNotEmptyConverter`, `StatusIsActiveConverter`).

**v3** — Found and fixed the only genuine *compile-blocker* in this project's history: `Platforms/Android/*` and `Platforms/iOS/*` entry points were entirely missing. Found via a structural-completeness check against what a MAUI SingleProject app requires to have an entry point at all — explicitly described in v3's own text as "a stronger check than reading the code and reasoning about it." (This is the origin of `PROCESS_v(N).md` Rule 4.) Also fixed a real runtime bug: `CoursePage.xaml`'s command bindings used `{RelativeSource AncestorType=...}` against a `BindingContext` type, which can never resolve via the visual tree — every download/delete button was silently dead. Wired the discarded course-level zip URL into a downloadable `Artifact`. Isolated zip extraction into per-artifact subfolders. Throttled progress events (~10/sec instead of per-chunk). Had `github.com` network access this one round only (fetched the real Open Sans font); did not have `nuget.org` access, so `dotnet restore` still wasn't possible. Deliberately deferred, not fixed: re-fetch duplicating rows; Pause being dead code.

**v4** — Fixed the re-fetch duplication v3 deferred (`FindArtifactBySourceUrlAsync`/`FindLectureAsync` reconciliation). Isolated zip-extraction failure from download success (a failed extraction no longer overwrites a successful download's `Completed` status with `Failed`). Split Pause from real failure via `catch (OperationCanceledException)` → `Paused` (fixes the status *model*; does not wire up a UI caller). Corrected a stale docstring referencing a method, `TryScrapeCourseAsync`, that never existed anywhere in the codebase. Closed with a process note — "keep each round's own response scoped to what actually fits... land a smaller fully-checked version rather than rush a larger patch" — that is a real, generic ancestor of what v9 would later name the Price Is Right rule, but is not that rule itself and should not be cited as its origin (a correction to v13's own prior draft, which had misattributed this).

**v5** — Fixed a real bug colliding with v4's own fix: `HttpClient`'s default 100-second timeout could fire mid-download on a large lecture video with nothing wrong, throwing `OperationCanceledException` — which v4's new catch block had just started mapping to `Paused`, mislabeling a plain timeout as a user action. Fixed via `Timeout = Timeout.InfiniteTimeSpan`. Explicitly named the resulting trade-off: no stall/watchdog detection for a connection that goes silent without closing. Restated v4's scoping note verbatim ("Same process note as v4 carries forward").

**v6** — Fixed a double-tap reentrancy bug: nothing stopped a second tap on an already-`InProgress` row from racing a second concurrent `DownloadAsync` call against the same file, which corrupted the shared progress-tracking dictionaries and froze the UI while the original download kept running invisibly. Fixed with a same-row guard at the top of both download commands. Restated the v4/v5 scoping note again.

**v7** — Fixed a related race: Delete could run against a row whose (re-)download was actively `InProgress`/`Extracting`, deleting the file out from under the open write handle and then losing to a later DB write from the still-running download, leaving the row reporting `Completed` for a file that no longer existed. Fixed with the same guard shape as v6, on the delete commands. Restated the scoping note again.

**v8** — Fixed a pre-existing bug (not introduced by v7, found on re-read): re-downloading an already-`Completed` file could get a `416 Range Not Satisfiable` from any server that implements HTTP Range correctly, which fell through unhandled into a generic failure. Verified the tool actually detects problems (not just staying quiet) by deliberately injecting a typo and an unbalanced brace into a scratch copy and confirming both were flagged. Explicit header note: "compile it" has been priority #1 since v1 and is now a 7-round-old structurally-impossible blocker, not an oversight — flagged as worth surfacing to a human rather than assuming a future round's environment differs.

**v16** — One round, landed in two parts after the person asked directly whether there was room for more; both folded into this single entry rather than split into v16/v17, per the person's explicit instruction.

*Part 1 — the confirmed bug from `SUPPLEMENT_v15.md`:* every downloaded file (and the SQLite DB) was written under `FileSystem.AppDataDirectory`, which Microsoft's own MAUI docs confirm resolves to the iOS **Library** directory — permanently hidden from the Files app regardless of `Info.plist`'s `UIFileSharingEnabled`/`LSSupportsOpeningDocumentsInPlace` (set since v1 specifically to expose downloads there). Also picked up SUPPLEMENT_v15's lower-priority item: the OCW label regex was re-confirmed sound (re-checked against a second live course page) and not loosened, but near-miss labels now get collected (`ScrapedCourse.UnmatchedResourceLabels`) instead of silently vanishing, surfaced via `CourseViewModel`'s post-fetch `StatusText`.
