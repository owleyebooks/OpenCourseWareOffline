## Per-risk verdicts

### 1. iOS WKWebView local file access: REAL, unmitigated in code
`Views/ArtifactViewerPage.xaml.cs:LoadArtifact` sets `Viewer.Source = new UrlWebViewSource { Url = new Uri(fullPath).AbsoluteUri }`. The absolute-URI form was a deliberate v19 dodge of dotnet/maui#10674's *relative*-URI crash (confirmed in `archive/v43-process-rules/AUDIT_TRAIL_v43.md` v19), but that issue is about the crash, not about resource scoping. The checklist's actual concern is `loadFileURL(_:allowingReadAccessTo:)`: whether MAUI's iOS handler grants the HTML file's *folder* read access so local CSS/images/JS load. Nothing in `Platforms/iOS/` addresses this (only `AppDelegate.cs`, `Info.plist`, `Program.cs`; no custom `WebViewHandler`). Verdict: real risk, no mitigation present, needs a physical iOS device to adjudicate; the documented fix (custom iOS `WebViewHandler` calling the native API) stands as the fallback. (Note: `OcwScraperService` saves scraped HTML pages as local files, so HTML artifacts with local subresources are in scope (not a hypothetical).)

### 2. MediaElement seek-on-open race: REAL, unmitigated in code
`Views/VideoPlayerPage.xaml.cs:OnMediaOpened` immediately awaits `Player.SeekTo(...)` with the saved position; `VideoPlayerPage.xaml` sets `ShouldAutoPlay="False"`. This matches the documented seek-after-`MediaOpened` pattern (and the code's own comment explains why: Duration/seek targets aren't meaningful earlier), but there's no state gate; nothing waits for the platform decoder (ExoPlayer/Media3 on Android, AVPlayer on iOS) to actually be ready. Verdict: real risk, no mitigation present. The checklist's suggested workaround (defer seek until player state reaches Playing/Paused) is the right experiment, but only a physical device can validate it; emulator decoder timing is not faithful.

### 3. Android PDF hand-off via FileProvider: likely MITIGATED BY DESIGN, still unconfirmed on device
This is the one where static analysis moved the needle. The checklist's feared failure ("Essentials' auto-generated FileProvider doesn't have `sharing-root` mapped") was already addressed by prior design: `ArtifactViewerPage.xaml.cs:OnOpenPdfClicked` deliberately copies the PDF into `FileSystem.CacheDirectory/sharing-root/` (the literal default path covered by Essentials' bundled `microsoft_maui_essentials_fileprovider_file_paths.xml` (`cache-path` → `sharing-root`), verified live in `archive/v43-process-rules/AUDIT_TRAIL_v43.md` v19, which also deliberately avoided declaring a custom `<provider>` (authority collision is a documented bug source). The v21 follow-up added the `<queries>` block (`ACTION_VIEW` + `application/pdf`) to `Platforms/Android/AndroidManifest.xml` for Android 11+ package visibility. So the failure mode the checklist names should already be covered; residual device risks are narrower (no PDF app installed, per-device URI grant quirks on API 34/35). Verdict: mitigated by existing design pending device confirmation; do **not** add `provider_paths.xml` preemptively; only if the device test actually throws.

### 4. CollectionView progress-update thrash: REAL, partially mitigated
Mitigation present: `Services/DownloadManager.cs:121` throttles progress events to `minReportIntervalMs = 100`, and `ViewModels/CourseViewModel.cs:344` `OnProgressChanged` marshals via `IMainThreadDispatcher.BeginInvokeOnMainThread` (testable, not the static `MainThread`) before setting the two `[ObservableProperty]` fields on the bound `Artifact`/`Lecture`. But: the throttle is *per download* (concurrent downloads multiply events), each event fires two `PropertyChanged` notifications into `CoursePage.xaml`'s two `CollectionView` row templates (`ProgressBar Progress="{Binding Progress}"`, `StatusIsInProgressConverter` visibility). Whether 100 ms holds up while scrolling on a real device is a tuning question, not a correctness one, and the final-tally event after the read loop means completion is never lost regardless. Verdict: real risk on device, partially mitigated; the one-line 100→250/500 bump is the documented fallback once a device session measures jank.
